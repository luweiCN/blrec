# 虚荣模型数据远程化与 Vision Worker

日期：2026-08-17

## 为什么改

现有 Vision Lab 会把 NAS 上的候选图片和缩略图复制到本机。候选增长到数万张后，
同步既慢又容易失败，本机也长期保存了完整录像、原图、缩略图、数据集和训练产物。
同时，数据集生成和训练进程与 Web 服务运行在同一个进程体系内，模型发布依赖逐台 SSH，无法形成
稳定的“收集 → 复核 → 训练 → 验收 → 发布 → 继续收集”闭环。

## 目标架构

### NAS：数据与控制面

Vision Lab 作为独立容器运行在 NAS，直接挂载：

- `/data`：标注库、不可变数据集、训练记录、模型包和少量派生缓存；
- `/candidates`：Analysis Worker 产出的候选图片与 JSON；
- `/published-models`：已经发布、供 Analysis Worker 下载的不可变模型包。

“刷新素材”只扫描候选 JSON 并建立数据库索引，不复制图片。浏览器打开某一条记录时，
由 NAS 按需返回对应图片。训练快照仍然是自包含、不可变的永久资产。

NAS 只承担前端、轻量 API、任务调度、元数据索引和按需文件返回，不执行批量图片解码、
预标、数据集物化、模型训练、批量验收或模型打包。

### Mac Studio：可插拔 Vision Worker

Mac Studio 运行独立 Vision Worker。它由用户启用或暂停，可声明自己支持的数据处理、训练、
验收和打包能力：

1. 使用专用 token 向 Vision Lab 领取兼容自身能力的任务；
2. 对候选做批量预识别/补齐元数据，或按轻量数据集清单从 NAS 按需下载素材；
3. 在 Worker 本地完成裁切、缩放和不可变数据集物化；
4. 使用 MPS 训练，逐 epoch 回报进度、指标和日志；
5. 执行批量验收、模型包构建并上传 ONNX、数据集快照、模型元数据和校验值；
6. 本地任务缓存可用于同一任务断点恢复，完成后可按保留策略清理。

Vision Lab 容器不安装 PyTorch/Ultralytics，也不占用 NAS 进行图片批处理或模型训练。
这台电脑只在 Vision Worker 被明确启用时执行重活；关闭 Worker 不影响 NAS 上的标注页面。

### Analysis Worker：模型消费面

通过验收的七个模型组成不可变模型包。发布时只更新 NAS 上的“期望模型包”指针。
每个 Analysis Worker 在领取下一项任务前检查版本：

- 相同：继续领取任务；
- 不同：下载、校验、解压并原子切换，然后重启自身；
- 校验或启动失败：保留上一版本并上报错误。

已经领取的任务不会在处理中途切换模型。

## 人工纠正与训练回流

管理后台现有对局编辑器继续作为业务真值入口。保存时遵循三层数据：

1. **模型原始输出**：永远保留，用于衡量模型当时为什么出错；
2. **人工覆盖**：继续写入 `vainglory_match_overrides`，重跑后仍生效；
3. **训练候选**：当人工值与模型值不同且存在结果图时，写入
   `vision-data/candidates`，来源为 `manual_correction`，包含 before/after、模式、
   阵容、主播英雄和模型包版本。

人工纠正候选排在普通候选之前。结算图可以安全确定 `match_flow`、
`result_panel`、`not_select` 和人工确认后的 `match_mode`；英雄标签只有在头像位置由
检测模型找到后才进入英雄身份训练，避免把位置错误当作英雄真值。

## 筛选维度

统一打标页至少支持：

- 状态：待确认、部分确认、已确认、已跳过；
- 来源：人工纠正、Worker、新模型预填、历史结算、旧人工标注；
- 场景：HUD、积分板、结算界面、英雄选择、其他；
- 模式：3V3、5V5、大乱斗、看不清；
- 英雄：已确认或模型建议中包含某英雄；
- 置信度：低置信、边界、高置信；
- 主播、视频/分 P、模型包版本、时间范围。

数据面板按同样维度给出数量，使人工只处理真正缺少的组合，例如
“大乱斗 + 英雄选择 + 人工未确认”。

## 存储生命周期

- **候选**：可清理。未人工确认、未进入任何数据集快照且超过保留期时才允许删除；
- **人工确认但未冻结**：必须保留；
- **不可变数据集 train/val/test**：永久保留；
- **成功模型、验收记录、已发布模型包**：永久保留；
- **缩略图、打包缓存、失败训练的非断点中间文件**：可重建，可按容量清理；
- **完整录像**：不再因打标自动下载；只有用户明确要求预览/重新抽帧时才临时缓存。

## 网络边界

- 浏览器到 NAS 的图片读取使用 HTTP 按需加载；
- Vision Worker 的素材下载、数据集/模型上传使用独立 token；
- Analysis Worker 的模型包下载复用现有 Worker token；
- 大流量下载、上传继续经过既有网络用途与选路配置；任务内出口保持稳定；
- 正式镜像只由 GitHub Actions 构建，NAS 从 GHCR 拉取，本机不运行 Docker。

## 迁移顺序

1. 发布支持 NAS 直读候选和 Vision Worker API 的 Vision Lab 镜像；
2. 在 NAS 创建独立持久目录并迁移 `lab.db`、永久数据集、模型与必要原帧；
3. 校验 SQLite `quick_check`、文件数量和随机样本哈希；
4. 启动 NAS Vision Lab，确认旧标注、测试集和模型记录完整；
5. 在 Mac Studio 安装可暂停的 Vision Worker；
6. 发布支持自动模型包更新的 Analysis Worker；
7. 确认 NAS 副本和备份后，清理本机派生数据。
