# BLREC 3.0.0-beta.43

这是升级虚荣对局识别流程、补齐任务中心人工处理入口，并恢复简介、评论与视频分段历史积压的 NAS 灰度测试版。

## 对局分析

- 新流程先用 `multi-v2` 每 5 秒分类一次直播画面，推断实际对局段和模式，再只对结算候选窗口执行 4 FPS 精扫；退出信号回归与缺口补扫用于找回旧流程容易错过的短暂结算页。
- 结算检测优先使用新的 `result-detector-v1` 模型。Mac Worker 可配置 1～8 个独立领取线程，每个线程持有自己的客户端与心跳；特殊主播仍可固定使用 4 FPS 全量兜底。
- “对局分析任务”按级联扫描显示分类采样帧、推断对局段、精扫区间、候选验证、OCR 排除和已确认对局，并对重复心跳日志去重。

## 管理页面

- “最近完成”按分 P 展示识别截图，“接下来处理”按整场直播展示识别截图；点击后默认打开第一张，可用按钮或键盘左右键切换，并显示直播、分 P、时间和图片序号。
- 两个任务板块都可直接打开整场直播详情，包括尚未识别出任何对局的排队直播。
- “未识别英雄”和“主播英雄待确认”均支持整场重试、单局重试与忽略。忽略只写入独立抑制记录，不删除对局、截图或统计；后续重试会自动解除对应抑制。

## 发布 worker

- 简介、战绩评论、置顶评论和视频分段继续由一个专用发布服务收口，内部拆分为任务发现与实际投递两个独立循环，发现历史任务时不会再饿死已经准备好的发布步骤。
- 单条失败记录不再阻塞同一投稿账号的其他直播；普通历史积压改为从最旧记录开始处理，人工重试仍保持最高优先级。
- 已经完成简介和评论、但视频分段仍未执行的记录会从原步骤状态继续，不重复已经确认的远端操作。

## 升级说明

- 新增数据库迁移 0060，用于保存“未识别英雄”和“主播英雄待确认”的独立忽略状态。升级前必须先执行数据库备份并确认 SQLite `PRAGMA quick_check` 为 `ok`。
- 虚荣分析算法版本保持 18，不会自动重扫所有历史直播；需要用新算法纠正的直播可在待确认列表执行整场或单局重试。
- 使用远程分析模式时，Mac Worker 也必须切换到本标签代码、确认 `multi-v2.onnx` 和 `result-detector-v1.onnx` 存在，并重启 LaunchAgent。
- 不新增环境变量或持久化目录挂载，可从 `3.0.0-beta.42` 直接升级；必须继续使用固定镜像标签并保持现有配置、日志、录像、收藏、片段和结算截图挂载不变。
