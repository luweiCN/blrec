# BLREC 3.0.0-beta.42

这是把现有虚荣对局分析 Worker 从 NAS 完整迁移到 MacBook Pro 的候选版本。

## 分析 Worker

- NAS 保留现有任务队列、当天直播优先级、SQLite 数据、人工覆盖、统计以及简介、评论和视频分段发布；当前任务完成后，下一次领取仍由原 `claim_next` 决定当天直播或历史稿件。
- MacBook Pro 原生 Worker 会先把对应分 P 读取到本地缓存，再按 4 FPS 解码，使用 ONNX Runtime CoreML Provider 运行现有结算模型，并调用 Mac 本机 OCR 和英雄识别，最后将完整结果及结算截图写回 NAS 原有 `complete_part` 流程。
- 单局重新识别、英雄补认和主播位置补认也移到 Mac，避免这些入口在关闭 NAS 本地分析循环后失效。
- Worker 使用独立令牌访问派单接口，视频使用短期签名地址；运行中每 30 秒回传进度和任务中心日志。Mac 进程异常退出后，超过 3 分钟的任务会在 Worker 恢复领取时重新排队。
- 提供 `blrec-analysis-worker run` 命令和 macOS LaunchAgent 模板，不使用 Docker，也没有 CPU/GPU 人工限额。

## 配置

- NAS 设置 `BLREC_VAINGLORY_WORKER_MODE=remote` 后不再加载结算模型、英雄识别器或 OCR 客户端，也不启动本地扫描/OCR 循环。
- NAS 与 Mac 必须配置同一个随机 `BLREC_ANALYSIS_WORKER_TOKEN`；推荐存入权限为 `600` 的独立文件，不写入仓库或日志。
- Mac Worker 需要可访问 `http://192.168.50.24:2234`，本机 OCR 默认使用 `http://127.0.0.1:18080`。

## 升级说明

- 不新增数据库迁移，虚荣分析算法版本保持 18，不会自动重排已经完成的全部历史分 P。
- 切换远程模式时，NAS 上尚未完成的本地扫描或 OCR 分 P 会退回整分 P 队列，随后由 Mac 从头处理，避免跨机器传递半成品候选。
- 在 Mac Worker 已成功领取测试任务前不要关闭 NAS 本地模式；确认完整结果可写回后再设置远程模式。
- 新模型及打标工具不在本版本实现，后续工作提示词见 `docs/prompts/deepseek-vainglory-result-page-model.md`。
