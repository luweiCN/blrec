# BLREC 3.0.0-beta.34

这是针对 NAS 连续运行审计结果的公开测试版，同时改善 B 站直播观看过程中的高光标记体验。本版重点修复快速复播漏录、强制删除残留、投稿素材永久等待和上传网络状态误报。

## 连续运行修复

- 开播确认的 10 分钟冷却改为只约束同一场直播；检测到新的开播时间后会立即确认，不会沿用上一场的冷却而漏掉快速复播。
- 强制删除先停止录制器，让最后一个分片进入后处理队列，再停止后处理器。暂时受阻的旧删除任务不再卡住后续任务，相同阻塞原因也不会高频重复写日志。
- 已结束的录制运行如果遗留零字节或缺失尾分片，后台会在 60 秒安全期后在线排除，投稿不再永久等待。非空文件不会被在线对账抢占，仍由真实后处理队列完成，避免与转封装和删源并发。
- 上传固定使用所选线路且不自动切换出口。线路不可用发生在请求发送前时，任务进入有上限的退避重试；管理页始终显示上传自动接管关闭，通知只报告线路不可用。

## 全屏高光操作

- 普通模式继续在直播间标题栏显示“添加高光”，原有位置和操作流程不变。
- 进入网页全屏或系统全屏后，同一个按钮会移动到播放器右下角、原生控制栏上方；退出全屏后自动回到标题栏，不会重复生成按钮。
- 高光名称输入框在播放器内向上展开，保存成功或失败提示也挂载在播放器内，系统全屏时不会被全屏顶层遮挡。
- 插件直接监听网页全屏布局和浏览器 Fullscreen API 的状态变化，不依赖 B 站播放器内部易变的控制按钮类名。

## 验证状态

- 后端整仓 1,597 项测试通过、173 项按环境条件跳过。
- Angular 490 项测试通过；网络管理页覆盖旧设置中上传自动接管错误开启的归一化。
- 浏览器插件 33 项自动化测试、TypeScript 类型检查和生产构建均已通过。
- 快速复播、强制删除最后分片、删除队列阻塞、尾分片并发对账和上传线路不可用均有回归测试。
- 已覆盖网页全屏、系统全屏、退出全屏、单按钮约束和全屏反馈挂载。
- 当前自动化环境无法控制 Chrome 内部扩展管理页，因此尚未完成重新加载本次构建后的真实直播页端到端验收。

## 升级说明

本版本不新增数据库迁移、环境变量或目录挂载，可直接从 `3.0.0-beta.33` 升级。升级后建议继续保留旧服务但不要让它驱动第二份录制，观察 3～5 天并至少覆盖快速复播、正常投稿和本地删除各一次，再决定是否下线旧服务。

升级前仍应备份 `/volume1/docker/blrec-next/config` 和当前 Compose/环境配置。原 `/rec`、`/favorites`、`/clips`、配置、日志、录像、高光和投稿状态均会保留。
