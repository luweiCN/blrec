# 虚荣视觉模型训练与接入方案

状态：方案基线

最后更新：2026-08-09

## 系统边界

本文统一使用项目中的正式名称：

- **Vision Lab**：当前电脑上的非生产工作台，负责抽帧、预标、人工确认、冻结数据集、训练和离线验证。
- **Analysis Worker**：MacBook Pro 上的计算节点，负责抽帧、模型推理、OCR 和英雄识别。
- **BLREC Server**：NAS 上的业务协调与数据服务，不运行视觉模型。
- **模型包**：包含 ONNX、预处理规则、标签顺序、阈值、数据集版本、指标和文件校验值的不可变制品。单独一个 ONNX 文件不算完整模型包。

## 已确定的方案

1. 使用多个职责单一的小模型组成级联流程，不训练一个包办全部问题的大模型。
2. 不让所有模型逐帧运行。只有画面状态模型低频扫描全片；其他模型只在开局、结算或模式有歧义的短窗口运行。
3. 模型提供“证据”，时间线状态机负责判断一局从哪里开始、在哪里结束。单帧分类结果不能直接创建一场对局。
4. 胜利／失败动画只作为上下文，不作为结算点，也不决定向前还是向后寻找结算页。
5. 接受／拒绝匹配属于 `match_confirm`，不是 BP；它只作为 BP 模型的 `not_bp` 难负样本。
6. 3V3 和大乱斗不能仅凭普通战斗画面强行二选一。BP、天赋选择和黄色光栅可以提供大乱斗证据；证据不足时输出 `unknown`。
7. “没有检测到光栅”不能证明是 3V3，因为镜头可能根本没有拍到入口。
8. 增加训练图片不会自动增加模型参数或让单次推理变慢。模型大小主要由网络结构和输入尺寸决定；数据增加主要影响训练时间。

## 当前代码与目标状态

| 能力 | Vision Lab | Analysis Worker 当前代码 | 目标 |
|---|---|---|---|
| `multi-v2` 内容／阶段／模式三头分类 | 不在当前四个训练任务中 | 默认加载，用于每 5 秒粗扫和窗口推断 | 过渡期保留，最终由新的画面状态模型替换 |
| 结算面板检测 | 可冻结数据、训练、导出 ONNX | 默认加载 `result-detector-v1.onnx` | 用新数据迭代并纳入模型包 |
| BP 模式四分类 | 已有训练任务和 Worker 候选预标 | 尚未参与正式推理决策 | 识别开始锚点和 3V3／大乱斗／5V5 BP |
| 结算页／计分板三分类 | 已有训练任务和 Worker 候选预标 | 尚未参与正式推理决策 | 在结算候选窗口中复核检测结果 |
| 大乱斗光栅检测 | 已有专项标注和训练任务 | 尚未接入 | 只在 3V3／大乱斗有歧义时补充证据 |
| 新画面状态分类 | 尚未加入训练页面 | 尚未接入 | 低频构建整段录像的状态时间线 |

“Vision Lab 可以训练”与“MacBook Pro Worker 已经在使用”是两件事。任何新模型都必须完成离线验证、模型包冻结和 Worker 发布后，才能算进入生产流程。

## 实施顺序

### P0：恢复数据可读性并冻结基准集

2026-08-09 的目录整理把 Vision Lab 从 `scripts/vainglory_labeling` 移到了 `apps/vision-lab`，但 `lab.db` 中 32,734 条 `frame_path` 仍是旧绝对路径。图片实际存在于新目录，因此数据没有丢失，但 BP 和关键界面训练页会暂时显示为 0。

在开始下一次训练前必须：

1. 迁移数据库中的帧路径，并抽查图片可读。
2. 重新运行四个训练任务的数据统计。
3. 冻结一份不再参与训练的跨视频基准集，用它比较所有后续模型。

### P1：先稳定结算链路

先迭代结算面板检测器，再接入结算页／计分板分类器。原因是当前对局数据最终依赖真正结算页和 OCR，这条链路对业务结果影响最大，而且现有数据已达到试训量。

### P2：接入 BP 开始锚点

补齐大乱斗 BP 与 `not_bp` 后训练 BP 分类器。它负责给出开始锚点和初始模式证据，但必须等后续出现稳定的对局中画面，才能确认该 BP 确实进入了一局。

### P3：补充 3V3／大乱斗证据

补齐不同主播、不同设备的开放入口负样本，训练光栅检测器。它只处理 BP 和天赋证据不足的对局，不跑全片。

### P4：替换旧的全片粗扫模型

根据现有通用标注训练新的画面状态分类器，先以影子模式与 `multi-v2` 对比，再切换状态机。旧模型在完整录像回放验证通过前不删除。

## 完成标准

这套方案完成不是指“训练成功生成了 ONNX”，而是同时满足：

- 数据集有不可变版本，训练集、验证集和测试集按视频或录制场次隔离。
- 模型包明确记录输入预处理、标签顺序、阈值、指标和 SHA-256。
- 完整录像回放能正确配对最近的有效开始锚点与后续结算点。
- 证据冲突或不足时返回 `unknown`，不靠宽高比、未命中或单帧猜测模式。
- MacBook Pro 上记录实际耗时，级联方案相对当前基线没有不可接受的退化。
- 可以通过回退整个模型包或 Worker 版本恢复旧行为。
