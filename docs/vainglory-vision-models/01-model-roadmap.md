# 模型规划

## 结论

目标形态是 **5 个小模型 + 1 个时间线状态机**。模型各自只回答一个相对简单的问题，状态机把多个时间点和多种证据组合成一场对局。

最终计划保留的五种模型能力如下：

| 模型角色 | 初始输入 | 输出 | 是否扫全片 | 当前阶段 |
|---|---:|---|---|---|
| 画面状态分类器 | 224×224 | 7 类画面状态 | 是，每约 5 秒一帧 | 待增加训练任务；先由 `multi-v2` 过渡 |
| BP 模式分类器 | 224×224 | 3V3 BP／大乱斗 BP／5V5 BP／非 BP | 否，只扫开局窗口 | Vision Lab 已可训练，待补数据和接入 |
| 关键界面分类器 | 224×224 | 结算页／计分板／其他 | 否，只扫结算候选窗口 | Vision Lab 已可训练，待接入 |
| 结算面板检测器 | 640×640 | `result_panel` 边界框与置信度 | 否，只扫结算候选窗口 | 已在 Worker 使用，可重新训练 |
| 大乱斗光栅检测器 | 640×640 | `mode_gate` 边界框与置信度 | 否，只扫模式歧义窗口 | Vision Lab 已可训练，待补数据和接入 |

输入尺寸是当前第一版建议，不是散落在代码里的常量。正式值必须写进模型包清单，并保证训练和推理使用完全相同的预处理。

## 1. 画面状态分类器

### 它回答什么

它只回答“这个时间点处于哪一类画面”，用来低成本构建整段录像的时间线。第一版建议标签为：

| 标签 | 含义 | 状态机中的作用 |
|---|---|---|
| `not_vainglory` | 桌面、网页、其他游戏、直播贴片等 | 暂停对局判断，不把它误当成游戏外大厅 |
| `out_of_match` | 虚荣大厅、商店、英雄列表、资料页等 | 对局外状态；从对局流转到这里时形成结束边界候选 |
| `pre_match` | 排队、匹配确认、BP、阵容确认、进场加载 | 形成开始候选区间，但不单独证明已经开局 |
| `in_match` | 普通战斗和游戏内商店、计分板、暂停等覆盖层 | 证明已经进入实际对局 |
| `talent_select` | 大乱斗天赋选择 | 属于对局流，同时提供强大乱斗证据 |
| `post_match` | 胜负动画、真正结算页和其他赛后画面 | 仍属于本局流程；不能单独确定结算页位置 |
| `transition` | 黑屏、切应用、最小化、重连、异常中断 | 暂不下结论，等待前后稳定状态 |

低置信度不会被硬塞进某一类，而是在运行时变成 `unknown`。`unknown` 是推理结果，不建议把大量含义混杂的图片训练成一个类别。

### 它不回答什么

- 不负责判断 3V3、大乱斗或 5V5。
- 不负责精确定位结算面板。
- 不因看到胜负动画就认定结算页在它之后。
- 不因单帧 `pre_match` 就创建一局；用户可能在选英雄时退出并重新匹配。

### 与现有 `multi-v2` 的关系

当前 `multi-v2` 同时输出内容、阶段和模式三个头。它在过渡期继续负责粗扫，但普通战斗画面的 3V3／大乱斗模式头不再作为最终模式证据。

新状态模型稳定后，只替换“内容／阶段时间线”职责；切换前必须在同一批完整录像上以影子模式比较。旧模型在验证完成前保留，以便回滚。

## 2. BP 模式分类器

### 标签

- `bp_3v3`
- `bp_aram`
- `bp_5v5`
- `not_bp`

### 用途

当状态时间线发现 `pre_match` 区间，并且随后出现稳定的 `in_match` 时，Worker 在该开局附近取少量密集帧运行 BP 分类器：

1. 找到实际 BP 画面，记录开始锚点。
2. 给出第一份模式证据。
3. 保留多个开始候选；如果前一次 BP 退出而后面重新 BP，只让随后真正进入对局的最近候选生效。

`match_confirm`、排队、加载、阵容确认、游戏内画面和其他相似 UI 都应进入 `not_bp`。被遮挡或窗口化但仍能由人工确定模式的 BP 可以保留，并记录画面条件；完全看不清的图片应排除，不能伪装成 `not_bp`。

### 运行方式

- 不跑全片。
- 只在 `pre_match → in_match` 附近重扫。
- 先使用时间线上已有的代表帧；证据不足时才以 2～4 FPS 扩展几秒。
- 连续得到足够一致的结果后提前停止，避免固定跑满整个窗口。

## 3. 关键界面分类器

### 标签

- `result_page`：真正的赛后结算页面。
- `scoreboard`：对局仍在进行时打开的计分板或死亡计分板。
- `other`：胜负动画、普通战斗、商店、黑屏、加载和其他易混淆画面。

### 为什么结算检测器之外还需要它

结算面板检测器擅长回答“画面里有没有一个长得像面板的区域”，但计分板也可能很像。关键界面分类器从整张画面的上下文再判断一次，可以在 OCR 前挡掉计分板和赛后动画。

建议的确认条件是：

1. 处于状态机推断出的结算候选区间；
2. 结算面板检测器命中；
3. 关键界面分类器判为 `result_page`；
4. OCR 和版式检查通过。

这四层不要求每层都用同一个高阈值；最终阈值应通过整段录像回放确定。

## 4. 结算面板检测器

### 输出

单类 `result_panel` 检测，输出结算面板在原始画面中的边界框和置信度。边界框用于：

- 确认真正结算页候选；
- 从原始分辨率画面裁出 OCR 区域；
- 建立统一的 viewport 坐标变换，避免用整段视频宽高比猜游戏布局。

### 运行方式

它不需要 4 FPS 扫描整段录像。正常流程只在结束边界之前的候选窗口运行；短窗口没有结果时，再分段向本局开始处扩展。

计分板、死亡计分板、胜负动画、关闭结算面板后留下的背景、游戏窗口被遮挡和电脑端窗口化画面，都是必须覆盖的难负样本。

## 5. 大乱斗光栅检测器

### 输出与含义

它是单类 `mode_gate` 检测器：检测到黄色阻挡光栅，可以作为大乱斗强证据。

开放入口画面在训练时是非常重要的无框难负样本，帮助模型学会“黄色光栅”和“相同位置但没有光栅”的差别。但是运行时未命中可能有三种含义：确实没有光栅、镜头没拍到入口、画质太差。因此未命中不能直接变成 3V3。

### 运行方式

- 仅在 BP 和天赋证据仍无法区分 3V3／大乱斗时启用。
- 优先复用对局开始后约两分钟内已有的低频粗扫帧。
- 出现疑似命中后，才在附近短窗口增加采样确认。
- 一旦得到多帧一致的高置信度光栅证据即可停止。

## 模式证据如何合并

模型不直接互相覆盖结果。状态机保存每条证据的来源、时间、模型包版本和置信度，再按以下原则合并：

| 证据 | 可支持的结论 | 强度说明 |
|---|---|---|
| 清楚的 5V5 BP | 5V5 | 强证据 |
| 清楚的大乱斗 BP | 大乱斗 | 强证据 |
| 清楚的 3V3 BP | 3V3 | 强证据 |
| 多帧天赋选择 | 大乱斗 | 强证据 |
| 多帧黄色光栅命中 | 大乱斗 | 强证据 |
| 结算版式确认双方各 5 人 | 5V5 | 强证据 |
| 结算版式确认双方各 3 人 | 3V3 或大乱斗 | 只能排除 5V5，不能二选一 |
| 普通战斗画面的模式分类 | 仅用于候选排序和复核 | 弱证据，不单独定案 |
| 没检测到光栅／天赋 | 无结论 | 不是 3V3 证据 |

若两条强证据冲突，不用“分数高一点的覆盖分数低一点的”，而是将模式标为 `unknown`，保存冲突帧供 Vision Lab 复核。

## 暂时不单独训练的模型

### 普通战斗画面的 3V3／大乱斗二分类器

两种模式都是三人对三人，并共享地图主体。模型很容易记住主播、画质、UI 缩放或偶然背景，而不是真正的模式差异。第一阶段只使用 BP、天赋和光栅等可解释证据。若上线回放证明仍有大量无法判断的对局，再评估局部地图模型。

### 胜利／失败动画检测器

胜负动画在结算面板关闭后仍可能出现，时间上既可能位于真正结算页之前，也可能位于之后。它不能稳定定位结算点，因此不为它新增专用模型。

### 独立天赋选择模型

第一阶段由画面状态模型中的 `talent_select` 类承担，并在过渡期保留 `multi-v2` 的天赋信号。如果它在独立测试中仍然不够可靠，再把天赋识别拆成单独模型，而不是现在就增加第六个常驻模型。

### 一个包办全部任务的大模型

它会把不同数据需求、阈值和运行频率绑在一起；任何一个标签变化都要整体重训，也很难定位错误来自哪里。当前数据量和部署方式更适合小模型级联。

## 第一轮模型验收重点

单张图片指标只作为门槛，最终以完整录像为准：

- BP：重点检查 `match_confirm`、加载页和被遮挡 BP 是否被误当成有效开始锚点。
- 关键界面：基准集中不得把计分板当成最终结算页。
- 结算检测：优先保证真正结算页召回，再由关键界面分类与 OCR 控制误报。
- 光栅：优先保证精度；宁可没有证据，也不能把普通道路、黄色技能或 UI 认成光栅。
- 画面状态：重点检查 `pre_match → in_match` 和 `match_flow → out_of_match` 的连续性，而不是只看随机单帧准确率。
- 整体：模式证据不足或冲突时必须保留 `unknown`，不能为了提高“有结果率”而强猜。
