# 模型规划

## 结论

当前目标是 **4 个小模型 + 1 个时间线状态机**。一张图片只人工检查一次，
但可以同时给四个模型提供标签。旧 `multi-v2`、旧 BP/关键界面模型和黄色光栅
标注都保留，作为迁移数据或辅助证据，不再要求继续按旧流程重复打标。

| 模型 | 人工标签 | 运行位置与频率 |
|---|---|---|
| 对局流程分类 | `match_flow` / `not_match_flow` | Worker 每约 5 秒运行一次 |
| 英雄选择分类 | `not_select` / `select_3v3` / `select_aram` / `select_5v5` | 只在开局候选附近运行 |
| 对局模式分类 | `3v3` / `aram` / `5v5` | 只处理能看出地图的对局画面 |
| 结算面板检测 | `result_panel` 框 / `no_result_panel` | 只在结束候选窗口运行 |

每项还允许标为 `unreadable`。它表示“这张图无法为这个任务提供可靠真值”，
导出对应训练集时会排除，绝不能偷换成负样本。

## 1. 对局流程分类

它只回答“这一帧是否处在一局比赛的流程里”。

- `match_flow`：普通战斗、对局中积分板、游戏内商店、天赋选择、胜负动画、
  真正结算页等仍属于这一局的画面。
- `not_match_flow`：虚荣大厅、排队、匹配接受/拒绝、英雄选择，以及桌面、音乐
  播放器和其他非对局画面。
- `unreadable`：切换应用、严重遮挡、黑屏或仅凭这一帧无法可靠判断。

它不需要另外学习“是不是虚荣”。非虚荣画面自然属于 `not_match_flow`；训练数据
应覆盖常见桌面、播放器、网页和其他游戏，但不需要穷举世界上所有应用。

状态机只相信连续观测：从非对局稳定进入对局才确认开局，从对局稳定退出后才
产生结束边界。单帧误判不能直接创建或结束一局。

## 2. 英雄选择与模式分类

这一个模型同时回答“是不是英雄选择”和“是什么模式的英雄选择”。

- `not_select`：排队、接受/拒绝、阵容卡片、加载、对局画面和其他非英雄选择。
- `select_3v3`：能可靠看出是 3V3 的盲选或 BP。
- `select_aram`：大乱斗随机英雄选择。
- `select_5v5`：5V5 盲选或 BP。

匹配接受/拒绝明确属于 `not_select`。遮挡或小窗后仍能可靠判断时可以保留；模式
看不清时标 `unreadable`，不能为了凑负样本改成 `not_select`。

运行时只在开局候选附近调用。若多次进入英雄选择但前几次退出，状态机选择后来
真正进入对局之前最近的有效英雄选择锚点。

## 3. 对局模式分类

它只处理已经确定属于对局、并且画面本身能看出地图的帧，输出 3V3、大乱斗或
5V5。商店、三人积分板、严重遮挡等无法可靠区分 3V3/大乱斗的画面必须标
`unreadable`，不参与这个模型训练。

旧黄色光栅数据仍是很强的大乱斗证据，已迁移为 `aram` 模式标签；开放入口数据
迁移为 3V3 标签。旧框永久保留以便追溯，但新流程不要求继续圈光栅。后续若发现
整图模式分类仍不够稳定，再决定是否恢复局部光栅检测，当前不并行训练第五个模型。

## 4. 结算面板检测

正样本必须同时满足：

1. 人工确认为真正结算面板；
2. 画一个覆盖完整结算面板的大框。

一张图只保留一个完整结算框。积分板、死亡积分板、胜负动画、普通战斗、商店、
黑屏以及关闭结算面板后的背景都是负样本，不需要画框。旧积分板和商店框保留，
但新模型不用，也不要求重画。

Worker 会同时保留两类结算候选：本局中置信度较高、画面较完整的命中，以及模型
刚刚能命中的低置信边界帧。NAS 中已经识别出的历史对局结算截图也全部作为
`result_panel` 预标候选导入；它们仍需人工确认，不能直接冒充真值。

## 一张图如何复用

统一复核记录包含四项：

```text
match_flow_label
match_mode_label
hero_select_label
result_panel_label + 可选 result_panel 框
```

条件关系如下：

- 对局画面必须补“能看出的模式”，同时英雄选择固定为 `not_select`。
- 非对局画面不填对局模式，但必须判断英雄选择类型。
- 结算判断与前三项独立；真正结算正样本必须有框。
- 模型建议与人工标签分表保存。没有人工标签是“尚未判断”，不是负样本。

## 运行成本

四个模型不会逐帧一起运行。对局流程模型是唯一固定低频成本；英雄选择模型只跑
开局窗口，对局模式模型只跑已进入对局且需要模式证据的少量帧，结算检测只跑结束
候选窗口。增加训练图片会增加训练时间，但只要网络结构和输入尺寸不变，就不会让
ONNX 文件自动变大，也不会让单次推理自动变慢。

## 验收重点

- 对局流程：完整录像中的开局/结束边界连续稳定，不被短暂切应用截断。
- 英雄选择：接受/拒绝不能误报为英雄选择，被取消的选择不能建立空对局。
- 对局模式：按主播、设备和视频隔离测试，防止记住画幅或直播覆盖层。
- 结算检测：重点验证积分板难负样本和电脑端/小窗画面，优先保证真正结算召回。
- 整体：证据不足时保留 `unknown`，不使用宽高比或“没有检测到某物”强猜模式。
