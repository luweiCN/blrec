# 虚荣旧算法历史结果重跑计划

## 目的

当前历史稿件处理中，部分直播由旧分析算法产出，部分直播已经由
`timeline-v2` 和新模型包产出。旧算法存在漏局、把积分板误认为结算页、模式与
阵容人数冲突，以及对非《虚荣》片段反复扫描导致耗时失控等已知问题。

因此，需要在当前历史接入大批次完成后，再把仍只保留旧算法结果的直播统一用
新算法重跑一遍。

## 启动条件

这项重跑**不以 2026-08-12 创建的 275 项恢复任务完成为启动条件**，也不在当前
历史任务仍大量排队时提前执行。

启动前应满足：

1. 当前计划覆盖的整个历史接入范围已经处理完成，队列已经基本排空；
2. 覆盖范围由人工最终确认：可能只覆盖夏季赛，也可能覆盖全部约一万条历史稿件；
3. 当前新算法和模型包已经经过这一轮生产结果验收，版本保持稳定；
4. 已保存数据库备份，并生成只读清点报告。

范围尚未确认前，不自动创建第二轮重跑任务。

## 清点规则

清点必须依据数据库中的真实分析来源，不按稿件发布日期推测：

- 分 P 的 `analysis_summary_json.pipeline` 不是 `timeline-v2`，或者没有分析摘要，
  视为旧流水线结果；
- 同一直播全部分 P 都是当前目标新模型包时，不进入重跑；
- 同一直播同时包含新旧分 P 时，整场列为混合来源，默认整场重跑；
- 尚未分析、正在分析、导入未完成和媒体不可用的稿件单列，不能冒充旧算法已完成；
- 人工确认“无需扫描”、已删除或明确不属于《虚荣》的直播单独列出，不自动解除；
- 最终按直播场次去重，不能把分 P 数量当成直播数量。

## 执行流程

1. 先以 dry-run 生成不可变清单，统计旧算法、混合来源、新算法和无法判断四类数量；
2. 估算视频总时长、分 P 数量和预计 Worker 耗时，经人工确认范围后再入队；
3. 分批重跑，避免第二轮任务挤占仍未完成的首次历史接入任务；
4. 每一场保存重跑前快照，并记录旧、新管线和模型包版本；
5. 对比局数、结算时间、模式、阵容人数、主播英雄、重复／幽灵局和单位视频时长耗时；
6. 对新增局、删除局、模式变化和异常耗时自动生成复核清单；
7. 全部完成后输出最终报告，再决定是否替换或发布相关统计结果。

## 当前状态

- 2026-08-12 的 275 项恢复任务属于当前处理批次的一部分，不是本计划的启动门槛；
- 本计划当前仅记录，**未入队、未解除任何扫描排除、未触发全库重算**；
- 下一次动作应发生在整个目标历史范围完成后：先确认范围，再运行只读清点。
