# 录像库与对局索引产品重构草案

## 文档状态

- 产品总名称暂不决定。
- 统一管理录像的模块确定命名为“录像库”。
- 本文用于后续独立会话继续产品设计与实施，不代表现在立即迁移数据库。
- 当前历史稿件接入、对局识别和投稿后处理仍在运行；这些存量任务完成前，只做兼容现有模型的增量界面与性能改进。

## 为什么需要重构

当前系统以功能演进顺序形成了录制任务、录制历史、上传任务、稿件迁移、历史稿件接入、对局索引和片段等多个入口。它们在业务上彼此关联，但页面和术语把“内容”“来源”“远端副本”和“执行任务”混在了一起，导致以下问题：

- 从一场对局不能自然回到所属录像、分 P、播放位置和投稿稿件。
- 从一条录像不能一眼看到识别出的对局、投稿状态及正在执行的任务。
- 历史稿件、其他平台视频和手动导入视频未必有直播房间，无法以房间作为统一归属。
- 用户看到的是若干任务 ID 和状态，却难以理解最终内容是否已完整落库。

重构目标不是把现有功能换一套名字，而是建立稳定的内容关系，再把执行过程放到独立任务中心观察和恢复。

## 产品原则

1. 录像是来源无关的内容，不属于某个直播房间。
2. 直播房间、B 站稿件、其他平台地址和手动文件只是录像来源。
3. 对局是一等对象，每一局单独保存、检索和跳转，但仍归属于一条录像。
4. 投稿是录像在外部平台上的副本，不是录像本身。
5. 任务只表达执行过程，任务失败、重启或重试不能改变内容归属，也不能制造重复录像或重复对局。
6. 自动识别结果必须能表达“尚未处理”“主动放弃”“自动识别”“人工确认”，不能用空值把这些状态混在一起。
7. 新录播及其投稿优先于历史接入；历史任务可暂停、限速，并在异常退出后恢复。

## 核心对象

### 录像

录像库中的聚合对象，代表一次完整的可观看内容。它可以是一场直播、一个平台稿件或一组用户手动组合的视频，由一个或多个有序分 P 组成。

录像保存展示标题、主人公、来源、分 P、投稿、对局、片段和操作历史。录像可以没有直播房间，也可以同时保留多个来源线索。

### 录像分 P

录像时间线中的有序视频部分。对局开始和结束可以落在不同分 P，页面应向用户展示统一时间线，同时保留精确的分 P 内位置。

### 来源

说明录像从哪里获得，包括：

- 直播录制及可选的录制房间；
- B 站历史稿件；
- 其他平台视频；
- 用户手动导入的一个或多个文件。

来源负责追溯和必要时重新获取媒体，不决定录像的业务归属。

### 投稿

录像在 B 站等平台上的远端副本。投稿保存账号、稿件 ID、分 P 映射、审核状态、简介/章节/评论/置顶回填状态及投稿历史。

同一录像可以存在历次投稿；被迁移后将删除的来源稿件只能作为追溯线索，不能作为最终展示链接。

### 对局

录像中的一局游戏，从开局到结算单独建模。每局至少关联：

- 所属录像；
- 起止时间以及跨分 P 映射；
- 游戏模式、胜负、人头比和结算画面；
- 双方玩家与英雄；
- 录像主人公所在玩家及所用英雄；
- 自动识别版本、置信度和人工修正来源。

对局可按英雄组合、主人公英雄、玩家、模式、胜负、主播/主人公和时间检索，并能反向跳到录像详情、对应播放位置和远端稿件。

### 片段

从录像统一时间线截取的派生内容。片段必须保存来源录像和时间范围；创建片段是一个任务，但任务完成后的片段本身是内容。

### 任务

扫描、OCR、英雄识别、主人公识别、下载、转码、上传、投稿、评论和回填等执行过程。任务中心统一展示队列、优先级、阶段、进度、失败原因、下次重试时间和可执行操作。

任务中心不替代录像详情：录像详情展示与该录像有关的任务摘要，并能跳转到任务中心的过滤结果。

## 页面层级

### 录像库

列表以录像为单位，而不是以房间或上传任务为单位。可按标题、主人公、来源、时间、对局英雄、投稿状态和永久保留状态筛选。

录像详情建议包含：

1. 概览：标题、主人公、封面、来源、总时长和状态。
2. 分 P 与统一时间线：播放、下载、弹幕和片段入口。
3. 对局：紧凑摘要及进入完整对局详情的入口。
4. 投稿：当前稿件、历史稿件及简介/章节/评论回填状态。
5. 片段：从该录像生成的片段。
6. 任务与事件：当前任务摘要、失败诊断和完整操作历史。

在当前大重构开始前，现有“录播任务详情”先增加只读的对局摘要作为过渡：每局显示双方英雄头像、VS、人头比和胜方，不重复完整玩家数据。

### 对局库

列表以单局为单位，支持组合筛选。对局详情展示结算画面、双方阵容、基础数据和识别状态，并提供：

- 返回所属录像；
- 从本地或 B 站对应时间播放；
- 创建片段；
- 修正游戏模式、英雄及录像主人公英雄。

每局卡片头部直接显示录像主人公英雄。3V3 和大乱斗的新数据在英雄识别后使用同一张结算图同步判断主人公行；旧数据异步回填。状态必须区分：

- 等待历史回填；
- 已运行但置信度不足；
- 自动识别成功；
- 人工指定；
- 当前模式尚未支持，例如未适配的 5V5。

人工选择的真实含义是“该局蓝绿色一方中的哪位玩家是录像主人公”，界面可用其英雄作为主要选项，并以玩家名或行号消除重复英雄的歧义。

### 任务中心

独立页面汇总实时录播与历史接入产生的所有后台任务。实时录播的结算识别和当天投稿后处理优先，历史任务使用剩余容量。页面可按录像、任务类型、来源和状态筛选，并实时更新阶段进度。

## 关键关系

```text
来源 ──> 录像 ──< 录像分 P
           │
           ├──< 对局 ──< 玩家/英雄
           ├──< 片段
           ├──< 投稿 ──< 远端分 P/回填记录
           └──< 任务/事件
```

直播房间只会出现在一种来源记录上，不是录像、对局或投稿的必填外键。

## 一致性要求

- 同一来源重复接入必须落到同一录像或明确提示冲突，不能静默产生重复录像。
- 同一分 P 重新扫描应更新既有对局或生成可审计的新版本，不能简单追加重复对局。
- 任务在任何异常退出后可继续；已完成的阶段不重复产生远端副作用。
- 自动识别被人工修正后，后续重扫不得覆盖人工结果。
- 删除来源稿件不影响录像、对局和新投稿之间的关系。
- 未明确识别的主人公或主播保持为空，不凭标题强行绑定。

## 实施顺序

### 阶段 0：保持运行

- 让现有历史接入和迁移队列继续完成。
- 固化术语和产品关系。
- 只做兼容性 UI：录播详情展示对局摘要、对局详情补充主人公英雄状态与人工修正。
- 优化片段慢路径，但不迁移现有内容表。

### 阶段 1：建立只读关系

- 为现有录制场次、历史接入和迁移记录补齐统一录像标识。
- 在现有页面增加录像、对局、投稿和任务之间的双向跳转。
- 审计无法自动归并及缺少来源标识的数据，先进入人工处理列表。

### 阶段 2：迁移领域模型

- 建立来源无关的录像及分 P 关系。
- 将对局逐局绑定到录像统一时间线。
- 将投稿、迁移来源和历史稿件关系迁入统一模型。
- 使用可重复执行的回填任务迁移存量，并逐批核对数量与链接。

### 阶段 3：重组页面

- 上线录像库、对局库和任务中心的新导航。
- 录像详情成为内容关系的主要入口。
- 原录制历史、上传任务和历史接入页面逐步变为过滤视图或任务中心入口。

### 阶段 4：清理兼容层

- 存量数据核对完成后移除旧入口和重复字段。
- 最后决定并替换产品总名称及品牌资源。

## 验收场景

1. 从任意对局可一键找到所属录像、结算图、精确播放位置和有效的新稿件。
2. 从录像详情可看到所有分 P、逐局摘要、投稿、片段和后台任务，不必跨页面手工搜索 ID。
3. 没有直播房间的历史稿件、其他平台视频和手动导入视频都能建立完整录像与对局关系。
4. 输入若干英雄后能查到包含该阵容的具体对局，再反向播放原录像。
5. 自动识别不确定时状态清晰，人工修正后刷新、重启或重扫都不会丢失。
6. 程序在下载、识别、上传或回填途中退出，恢复后既不漏处理也不重复发布。

## 暂不处理

- 产品总名称与品牌视觉。
- 在当前批量任务运行期间重建核心表或删除旧数据。
- 为尚无真实样本验证的 5V5 主人公识别假装提供自动结果。
