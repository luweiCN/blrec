# 挂机计分、PVE 发布与内网站长纠错

## 目标

1. 把挂机计分改为：只要己方非本人队友挂机，输局不扣分；赢局按实际人数优势决定正常、奖励或折扣；本人挂机继续处罚。
2. 删除 Dashboard API 直接部署到阿里云的旧路径，阿里云只保留 Nginx/WireGuard 入口，正式后端只运行在 PVE。
3. 把外网页面的站长入口移除，在 PVE 内网提供无需记忆密钥的站长页面；可修改 AI/OCR 识别出的对局事实，保留审计、生成 Vision Lab 纠错样本并触发全量评分重算。

## 成功标准

- 单元/契约测试覆盖双方同数挂机时己方输局仍受保护，以及三类赢局计分。
- 线上 match 26835 改为 `protected_loss`、本局 0 分，并按时间顺序重算后续评分。
- GitHub workflow 不再存在“向阿里云安装 API”的逻辑；PVE 发布具有正式制品、备份、健康检查和回滚路径。
- 公网页面不显示站长入口、不接收站长密钥；PVE 内网页面可以编辑约定字段并显示模型值、置信度、来源与人工覆盖值。
- 每次人工提交原子地完成：事实覆盖 + 审计记录 + 模型纠错样本入队 + dashboard revision 更新；评分重算完成后页面再显示成功。
- 相关 Python、Angular、Vision Lab 测试和生产构建通过，部署后公网只读与内网写入边界均验证。

## 暂定业务规则

- “己方挂机”指主播本人之外的己方队员挂机；本人挂机单独适用重罚。
- 己方队员挂机且输局：无条件 0 分，不再抵消对方挂机人数。
- 己方队员挂机且赢局：己方挂机更多时少打多奖励；双方挂机相同则正常加分；对方挂机更多则折扣加分。
- 如果用户明确表示“本人挂机但队伍获胜也不处罚”，需在编码前单独调整这一条；当前沿用既定的本人挂机处罚。

## 约束

- 不操作本机 Docker 或 Chrome。
- 不覆盖主工作区和其他线程的未提交改动。
- 所有生产数据库写入与部署必须先备份并可回滚。
- 公网保持只读；内网写入仍需服务端信任边界、审计与 CSRF/来源保护，不能只靠隐藏按钮。
